## 错误描述

```javascript
// ❌ 错误代码
var floaty = $floaty.window(RelativeLayout);  // ❌ 错误，$floaty.window 不存在
var floaty = $floaty.newApp(xml);             // 可用，newApp 是应用级悬浮窗（系统级用 newSys）
```

## 正确代码

```javascript
// ✅ 推荐使用 $floaty.newSys()（系统级悬浮窗，权限更高）
var floaty = $floaty.newSys(`
<ui>
<frame w="200dp" h="300dp" bg="#FFFFFF">
<linear dir="v" w="max" h="max" gravity="center">
<text text="悬浮窗内容" textSize="16" />
</linear>
</frame>
</ui>
`);
floaty.setXY(100, 200);  // 设置位置
floaty.setWH(200, 300);  // 设置宽高
```

## 常用 API 速查

| 方法 | 说明 |
|------|------|
| `$floaty.newSys(xml)` | 创建系统级悬浮窗（正确方法） |
| `floaty.id(id)` | 获取控件 |
| `floaty.setXY(x, y)` | 设置位置（不是 setPosition） |
| `floaty.setWH(w, h)` | 设置宽高 |
| `floaty.touch(true/false)` | 设置是否可触摸（不是 setTouchable） |
| `floaty.close()` | 关闭悬浮窗 |
| `$floaty.closeAll()` | 关闭所有 |

## 系统级悬浮窗拖动实现

SysFloaty 和 AppFloaty **没有 `getXY()` / `getX()` / `getY()`**，只有 `setXY()` / `setX()` / `setY()`。实现拖动需要：

1. **用 JS 变量跟踪位置**（代替不存在的 getter）
2. **用 `view.onTouch()`**（XView 方法），不要用 Android 原生 `setOnTouchListener`
3. **MotionEvent 常量用数字**：`0`=DOWN, `1`=UP, `2`=MOVE, `3`=CANCEL

```javascript
// ✅ 正确拖动实现
let winX = 100, winY = 200;  // 跟踪变量

// onTouch 回调
function onDrag(event, view) {
    switch (event.getAction()) {
        case 0: // ACTION_DOWN
            dragStartX = event.getRawX();
            dragStartY = event.getRawY();
            winStartX = winX;
            winStartY = winY;
            return true;
        case 2: // ACTION_MOVE
            let dx = event.getRawX() - dragStartX;
            let dy = event.getRawY() - dragStartY;
            winX = winStartX + dx;
            winY = winStartY + dy;
            win.setXY(winX, winY);  // 用跟踪变量
            return true;
        case 1: // ACTION_UP
        case 3: // ACTION_CANCEL
            savePos(winX, winY);
            return true;
    }
    return false;
}

// 注册到多个视图，确保任意位置可拖动
win.id("rootFrame").onTouch(onDrag);
win.id("tvLog").onTouch(onDrag);

// ❌ 错误做法
// var p = win.getXY();           // getXY 不存在！
// win.setOnTouchListener(...);   // setOnTouchListener 不存在于 XView！
// android.view.MotionEvent.ACTION_DOWN  // 类可能找不到！
```

完整案例：`examples/$floaty - 悬浮窗/03.系统级悬浮窗/04.可拖动的日志窗口.js`

## 透明背景设置

`bg` 属性支持 `#AARRGGBB` 格式（`AA`=透明度 00-FF）。注意透明度要放在**内层容器**上：

```xml
<!-- ✅ 正确：透明度放在 linear 上 -->
<frame>
  <linear bg="#66000000">
    <linear dir="h" bg="#BB444444">...</linear>
    <scroll bg="#77333333">...</scroll>
  </linear>
</frame>

<!-- ❌ 可能不生效：透明度放在 frame 上 -->
<frame bg="#66000000">
  <linear>...</linear>
</frame>
```

透明度参考值：
- `#00` = 完全透明
- `#44` = 约 27% 不透明
- `#66` = 约 40% 不透明
- `#77` = 约 47% 不透明
- `#AA` = 约 67% 不透明
- `#BB` = 约 73% 不透明
- `#FF` = 完全不透明

## 字体大小设置

`textSize` 可直接用数字（如 `textSize="7"`），也可带 `dp`/`sp` 单位。纯数字更简洁，带单位更精确，根据需要选择即可。

```xml
<text textSize="7" />      <!-- 纯数字，简洁 -->
<text textSize="7dp" />    <!-- 带单位，精确 -->
```



## ScrollView 自动滚动常见问题

### 问题：新日志添加后滚动"慢一步"或底部"冒尖"

**现象：** 日志滚动显示时，最新一条日志总是慢一步（显示 29 但实际已到 30），或者底部总有日志内容"冒尖"显示不全。

**原因：** `setText()` 更新文本后，ScrollView 的布局尚未完成。此时立即调用 `fullScroll(FOCUS_DOWN)` 滚动的是旧内容的高度，导致位置不准。

**解决：** 用 `setTimeout(fn, 100)` 延迟滚动，等布局完成后再执行：

```javascript
// ✅ 正确：延迟 100ms 等布局完成
tv.setText(android.text.Html.fromHtml(htmlText));

try {
    var sv = scroll.getView();
    setTimeout(function() {
        sv.fullScroll(android.view.View.FOCUS_DOWN);
    }, 100);
} catch(e) {}

// ❌ 错误做法
// sv.fullScroll(FOCUS_DOWN);              // 立即执行，布局未完成，慢一步
// sv.post(function() { ... });             // post 在部分版本不稳定
// setTimeout(fn, 0);                       // 0ms 太短，布局仍未完成
```

> 注意：`setTimeout(100)` 只延迟滚动动作，日志文本是立即更新的，不影响实时性。

## 多悬浮窗共存问题

### 问题：新创建的浮窗触摸区域覆盖了旧浮窗

**现象：** 创建第二个 `$floaty.newSys()` 后，触摸旧浮窗（如日志窗）的区域，实际拖动的是新浮窗。

**原因：** XML 布局里用了 `h="max"` 且父容器没有固定高度时，窗口的触摸区域可能异常扩展，挡住后面的浮窗。

**解决：** 内层元素用固定高度，不要用 `h="max"`：

```xml
<!-- ✅ 正确：子元素用固定高度 -->
<frame w="36dp" radius="4dp">
<linear dir="v" w="max">
    <text id="btn" text="⏸" w="36dp" h="36dp" ... />
</linear>
</frame>

<!-- ❌ 错误：h="max" 可能导致触摸区域异常 -->
<frame w="36dp">
<linear dir="v" w="max" h="max">
    <text ... w="36dp" h="36dp" />
</linear>
</frame>
```

### 问题：悬浮窗不显示（无报错）

**现象：** `$floaty.newSys()` 没有报错，返回了对象，但屏幕上看不到浮窗。

**原因及解决：**

1. **子元素没有固定尺寸** — `<text>` 用 `w="max" h="max"` 但父容器没有固定高度时，子元素高度为 0：
   ```xml
   <!-- ✅ 正确：给固定尺寸 -->
   <text w="36dp" h="36dp" ... />

   <!-- ❌ 错误：父没固定高度时 max 等于 0 -->
   <text w="max" h="max" ... />
   ```

2. **用了 `<img>` 元素** — `$floaty.newSys()` 中 `<img>` 可能不支持，改用 `<text>`：
   ```xml
   <!-- ✅ 正确：浮窗里用 text 代替 img -->
   <text text="⏸" textSize="16" ... />

   <!-- ❌ 浮窗里 img 可能不显示 -->
   <img path="./res/icon/pause.png" ... />
   ```

3. **`h="auto"` 无效** — 浮窗 XML 不支持 `h="auto"`，去掉即可。

### 问题：`<card>` 的 padding 在 `$floaty.newSys()` 中可能不生效（待验证）

**现象：** `<card padding="3dp">` 包裹 `<img>` 时，padding 似乎没有参与布局测量，窗口实际宽度等于子元素尺寸，导致窗口位置计算偏差。

**疑似原因：** `$floaty.newSys()` 中 `<card>` 的内边距（padding）可能不参与布局测量，card 直接包裹子元素的实际尺寸。

**解决方案（经验证可行）：**

1. **窗口尺寸以最内层子元素为准** — 计算贴边位置时，只算 img/text 等实际有尺寸的元素：
   ```javascript
   var info = $screen.info();
   // 1dp = dpi / 160 (px)
   var winPx = Math.round(22 * info.dpi / 160);  // 仅 img 的 22dp
   _winX = info.w - winPx;
   _win.setWH(winPx, winPx);  // 显式锁定窗口尺寸
   ```

2. **用 `_win.setWH()` 显式锁定窗口尺寸** — 创建浮窗后调用 `setWH()` 固定宽高，保证 `setXY()` 的计算值和窗口管理器的实际占用一致：
   ```javascript
   _win.setWH(winPx, winPx);
   _win.setXY(info.w - winPx, ...);
   ```

3. **用 `$screen.info()` 获取屏幕数据** — 不要用 `$screen.getWidth()` / `$screen.getDensity()`，改用 `$screen.info()` 返回的 ScreenInfo 对象，它提供物理全屏尺寸和准确 DPI：
   ```javascript
   var info = $screen.info();
   // info.w      — 全屏宽度（像素）
   // info.h      — 全屏高度（像素）
   // info.dpi    — 屏幕 DPI
   // info.density — 密度因子（= dpi / 160）
   ```

4. **dp→px 换算**：`1dp = dpi / 160 (px)`，即 `px = dp × dpi / 160`

### 问题：`<img>` 用 `src`（内置图标）可以正常工作

**现象：** 之前认为 `$floaty.newSys()` 不支持 `<img>`，但实测使用内置 Material 图标（通过 `src` 属性）可以正常显示。

**正确用法：**
```xml
<!-- ✅ 正确：浮窗里用 src 引用内置图标 -->
<img id="pauseBtn" src="ic_pause_fill" w="22dp" h="22dp" />

<!-- ❌ 浮窗里用 path 引用外部 PNG 可能不显示 -->
<img path="./res/icon/pause.png" ... />
```

常用内置图标：`ic_pause_fill`、`ic_play_arrow_fill`、`ic_home_fill`、`ic_close_outline`、`ic_article_outline`。图标颜色用 `tint` 属性控制。

### 问题：浮窗间全局变量干扰

**现象：** 多个浮窗模块共存时，A 浮窗的拖动影响了 B 浮窗的显示。

**原因：** `(function(){return this;})()` 在 `require()` 的模块中不返回全局对象，导致跨模块单例失效或互相污染。

**解决：** 不要用 `global` 做跨模块单例共享，直接用模块级本地变量：

```javascript
// ✅ 正确：模块内直接用本地变量
var _win = null;
var _winX = 0, _winY = 0;

function create() {
    _win = $floaty.newSys(`...`);
    _win.setXY(_winX, _winY);
}

// ❌ 错误：通过 global 共享可能互相覆盖
var G = typeof global !== "undefined" ? global : (function(){return this;})();
G.__mySingleton = { win: null };
```

### 问题：点击回调中 require() 报 FAILED ASSERTION

**现象：** 在浮窗按钮的 `.click()` 回调中调用 `require()` 报 `IllegalStateException: FAILED ASSERTION`。

**原因：** 事件回调在后台线程执行，首次 `require()` 不在主线程，触发 AutoGOD 的线程断言检查。

**解决：** 在模块顶部提前 require，回调里直接用引用：

```javascript
// ✅ 正确：提前加载
var _module = null;
try { _module = require("modules/myModule"); } catch(e) {}

win.id("btn").click(function() {
    _module.doSomething();
});

// ❌ 错误：回调里首次 require
win.id("btn").click(function() {
    var m = require("modules/myModule");
});
```
