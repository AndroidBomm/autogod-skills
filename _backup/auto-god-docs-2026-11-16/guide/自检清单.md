## 一、XML 布局语法检查

### 1.1 根节点检查

- [ ] XML 文件**没有** `<?xml version="1.0"...?>` 声明头
- [ ] 根节点是 `<ui>`（不是 `<界面>` `<layout>` 或无根标签）
- [ ] 所有控件都包裹在 `<ui>...</ui>` 内

### 1.2 标签名检查

- [ ] 使用小写标签名：`<linear>` `<scroll>` `<frame>` `<relative>`
- [ ] **没有**驼峰命名：`<LinearLayout>` ❌ → `<linear>` ✅
- [ ] **没有** Android 全限定名：`<android.widget.LinearLayout>` ❌

### 1.3 属性名检查

- [ ] 方向用 `dir`：`dir="v"`（垂直）或 `dir="h"`（水平）
- [ ] 背景色用 `bg`：`bg="#FFFFFF"`
- [ ] 字体样式用 `typeface`：`typeface="bold"`
- [ ] 文字颜色用 `color`：`color="#333333"`（不是 `textColor`）
- [ ] 多值间距用逗号：`padding="10,20,10,15"`（不是空格）
- [ ] 宽高用 `w`/`h`：`w="max"` `h="wrap"`（不是 `layout_width`）

### 1.4 路径检查

- [ ] `$ui.layout()` 路径相对于项目根目录
- [ ] JS 在 `src/main.js`，XML 在 `src/main.xml`，路径写 `src/main.xml`

## 二、API 调用规范检查

### 2.1 API 名称检查

- [ ] 所有 API 名称拼写正确（参考各模块文档）
- [ ] 大小写正确（如 `$screen.getScreen()` 不是 `getscreen()`）
- [ ] 使用正确的模块前缀（`$act`、`$screen`、`$ocr`、`$http`、`$floaty`、`$file`）

**常见错误：**
```
❌ $act.clickk()        ✅ $act.click()
❌ $screen.getscreen()  ✅ $screen.getScreen()
❌ $ocr.detct()         ✅ $ocr.detect()
```

### 2.2 参数类型检查

- [ ] 坐标参数为整数（不是浮点数或字符串）
- [ ] 时长参数为数字（毫秒）
- [ ] 文本参数为字符串
- [ ] 配置对象格式正确

```javascript
// ❌ 错误
$act.click("500", "800");       // 字符串——错误
$act.click(500.5, 800.2);       // 浮点数——错误

// ✅ 正确
$act.click(500, 800);           // 整数
$act.click(Math.floor(500.5), Math.floor(800.2));  // 取整
```

### 2.3 参数完整性检查

- [ ] 必填参数都已提供
- [ ] 参数顺序正确
- [ ] 可选参数使用正确

**常见参数顺序：**
```javascript
// click: (x, y, dur?, delay?)
// move: (x1, y1, x2, y2, dur?, delay?)
// write: (content, path, encoding?)——注意内容在前！
```

## 三、权限申请顺序检查

### 3.1 权限依赖关系

- [ ] 无障碍权限在截屏权限之前申请
- [ ] 存储权限在文件操作之前申请
- [ ] 悬浮窗权限在创建悬浮窗之前申请

**正确顺序：**
```javascript
async function init() {
    // 1. 无障碍权限（优先）
    if (!$act.hasPermit()) {
        $act.getPermit();
    }
    
    // 2. 截屏权限
    if (!$screen.hasPermit()) {
        $screen.getPermit();
    }
    
    // 3. 悬浮窗权限
    if (!$floaty.hasPermit()) {
        $floaty.getPermit();
    }
}
```

### 3.2 权限检查函数

- [ ] 所有需要权限的操作前都有权限检查
- [ ] 使用正确的检查函数（`hasPermit()` 不是 `getPermit()`）

**权限检查表：**

| 操作 | 权限检查函数 |
|------|-------------|
| 手势操作 | `$act.hasPermit()` |
| 截屏操作 | `$screen.hasPermit()` |
| 悬浮窗 | `$floaty.hasPermit()` |
| 读取图片 | `$permit.readImage()` |
| 读取视频 | `$permit.readVideo()` |
| 读取音频 | `$permit.readAudio()` |

### 3.3 UI 线程权限申请

- [ ] UI 线程中使用非阻塞方式（`$permit.wza()`）
- [ ] 或使用线程执行阻塞函数

```javascript
// ✅ UI 线程：使用非阻塞方式
$permit.wza();

// ✅ 或放到单独线程中执行
threads.start(() => {
    $act.getPermit();  // 在线程中阻塞申请
});
```

### 3.4 ⚠️ 主线程阻塞红线（最容易让整个脚本「假死」）

> **背景**：AutoGOD 脚本默认跑在主线程上，而主线程就是 UI 线程。一个阻塞调用会把界面和所有
> `setTimeout` / 回调一起冻住 —— 现象是「点了按钮没反应、日志停在一行、进程还活着」，**不报错、不崩溃**，
> 极难排查。项目里已经因为这个坑浪费过几个小时。

- [ ] **绝不在主线程调用同步阻塞 API**（任何带 `Sync` 后缀的 root / shell / 文件操作）
- [ ] 长耗时操作放 `threads.start()` 或至少 `setTimeout()`，不要直接串在主流程里
- [ ] 每个可能不回来的异步调用都要有**自己的超时兜底**（`setTimeout` 计时，到点就走失败分支）
- [ ] UI 回调（`ui.id("x").click(...)`）里**不要**直接跑重活；先返回，再用 `setTimeout` 派发

**已实测的典型阻塞点（本项目踩过的）**：

| 调用 | 现象 |
|------|------|
| `$root.exeRootShellSync(cmd)` | 在已经 `ui.show()` 的实例里**永久不返回**（界面卡死、日志断在一行） |
| `$root.getPermit()` | 调用后**整个 root 通道废掉** —— `exeRootShellSync` 卡死、`exeRootShell` 回调也不触发 |
| 主线程里 `sleep()` 循环 | 界面无响应、所有 `setTimeout` 延迟执行 |

```javascript
// ❌ 错误：主线程直接同步跑 root
let out = $root.exeRootShellSync("iptables -S OUTPUT");   // 可能永久卡死

// ✅ 正确：异步 + 自己的超时兜底
function runRoot(cmd, cb) {
    let done = false;
    let to = setTimeout(function () {
        if (done) return;
        done = true;
        $log.w("root 超时: " + cmd);
        cb(new Error("timeout"), "");
    }, 12000);

    $root.exeRootShell(cmd,
        function (line) { /* 输出行 */ },
        function (err) { if (!done) { done = true; clearTimeout(to); cb(err, ""); } },
        function (code) { if (!done) { done = true; clearTimeout(to); cb(null, String(code)); } }
    );
}
```

> 详细案例与根因见 `guide/踩坑记录.md` 第十章、第十一章。

## 四、异步操作处理检查

### 4.1 async/await 使用

- [ ] 所有异步函数使用 `async` 声明
- [ ] 所有异步调用使用 `await` 等待
- [ ] 异步函数调用在 async 上下文中

```javascript
// ✅ 正确
async function main() {
    await $act.getPermit();
    await $screen.getPermit();
    let img = await $screen.getScreen();
    // ...
}
```

### 4.2 回调函数

- [ ] 回调函数参数正确
- [ ] 回调中异常已处理
- [ ] 避免回调地狱（使用 async/await）

```javascript
// ✅ 回调方式
$http.download(url, path,
    (cur, total, percent) => { /* 进度回调 */ },
    () => { /* 完成回调 */ },
    (err) => { /* 错误回调 */ }
);

// ✅ async/await 方式（推荐）
async function download() {
    try {
        await $http.download(url, path);
        log("下载完成");
    } catch (e) {
        log("下载失败: " + e);
    }
}
```

### 4.3 ⚠️ 回调「写了吗」不等于「跑了吗」

- [ ] 不要靠「回调里打了日志」判断回调是否执行 —— **日志本身也可能因为线程问题不输出**
- [ ] 验证回调是否执行，要在回调里**改一个 JS 变量**，然后回到主流程读这个变量
- [ ] 异步调用**不要和同步调用混用**（见 §3.4：混用会毒化整条通道）

```javascript
// ✅ 用「改变量」而不是「打日志」来验证回调是否真的执行
let flag = "none";
let lines = 0;

$root.exeRootShell("id",
    function (line) { lines++; },
    function () { },
    function () { flag = "done"; }
);

setTimeout(function () {
    log("flag=" + flag + " lines=" + lines);   // flag=none lines=0 → 回调根本没跑
}, 3000);
```

**回调不触发时，按这个顺序排查**：

1. 换「改变量」的方式复验一次（排除日志通道问题）
2. 检查有没有在之前调用过 `$root.getPermit()`（会毒化 root 通道）
3. 检查有没有在同一个实例里混用过同步版本（`exeRootShellSync`）
4. **换启动方式复验** —— 用 `adb broadcast runJs` 启动的实例可能行为异常（见 `guide/Agent执行协议.md` 第三章 3.3）

## 五、资源释放检查

### 5.1 图像资源

- [ ] 所有 `Image` 对象使用后调用 `recycle()`
- [ ] 使用 `try-finally` 确保释放
- [ ] 避免重复释放

```javascript
// ✅ 正确：try-finally 确保释放
let img = null;
try {
    img = $screen.getScreen();
    // 使用图片...
} finally {
    if (img != null) {
        img.recycle();
    }
}
```

### 5.2 悬浮窗

- [ ] 脚本退出时关闭悬浮窗
- [ ] 使用 `events.on("exit", ...)` 注册退出回调

```javascript
let floaty = $floaty.newApp(xml);

events.on("exit", () => {
    $floaty.closeAll();
});
```

## 六、异常处理检查

### 6.1 try-catch 包裹

- [ ] 所有关键操作包裹在 try-catch 中
- [ ] 异常信息记录到日志
- [ ] 异常后资源已释放

```javascript
try {
    let node = $act.selector().text("按钮").waitFirst(3000);
    if (node != null) {
        node.click();
    }
} catch (e) {
    log("操作失败: " + e);
}
```

### 6.2 空值检查

- [ ] 节点查找结果检查 null
- [ ] OCR 识别结果检查 null
- [ ] 数组访问检查索引范围

```javascript
// ✅ 节点空值检查
let node = $act.selector().text("按钮").waitFirst();
if (node != null) {
    node.click();
} else {
    log("未找到按钮");
}

// ✅ OCR 空值检查
let point = $ocr.getPoint("文字");
if (point != null) {
    $act.click(point);
} else {
    log("未识别到文字");
}
```

### 6.3 超时处理

- [ ] 所有等待操作有超时时间
- [ ] 超时后有默认行为或错误处理
- [ ] 避免无限等待

```javascript
// ✅ 带超时的等待
let node = $act.selector().text("按钮").waitFirst(5000);  // 5秒超时
if (node == null) {
    log("等待超时，未找到按钮");
    // 执行备用方案
}
```

## 七、性能优化检查

### 7.1 截屏频率

- [ ] 避免循环中频繁截屏
- [ ] 使用缓存或降低截屏频率
- [ ] 指定截屏范围（减少数据量）

```javascript
// ✅ 降低截屏频率
for (let i = 0; i < 100; i++) {

        // 处理...

    }
}
```

### 7.2 OCR 优化

- [ ] 指定识别范围（region）
- [ ] 使用灰度化或二值化加速
- [ ] 选择合适的引擎（ncnn 最快，mlkit 最准）

```javascript
// ✅ 指定范围 + 灰度化
let result = $ocr.detect({
    region: [0, 0, 500, 200],  // 缩小识别范围
    gray: true                  // 灰度化加速
});
```

### 8.2 注释规范

- [ ] 函数有文档注释（功能、参数、返回值）
- [ ] 关键逻辑有注释说明
- [ ] 复杂算法有注释解释

```javascript
/**
 * 安全点击节点
 * @param {object} selector - 选择器配置
 * @param {number} timeout - 超时时间（毫秒）
 * @returns {boolean} 是否点击成功
 */
function clickNode(selector, timeout = 3000) {
    let node = $act.selector()
        .text(selector.text || null)
        .waitFirst(timeout);
    
    if (node != null) {
        node.click();
        return true;
    }
    return false;
}
```
